# Где живёт текст: UI, мир или микс

Пользователь выбирает режим в шаге 5. Ты рекомендуешь один (первым вариантом) и в `description` каждого варианта описываешь, как он будет выглядеть **в выбранном стиле** — конкретно: «субтитры Garamond внизу + подсказки [E]», «краска на стенах под фонарём + табло».

## Как рекомендовать

| Сигнал | Склоняет к |
| --- | --- |
| Плотный текст (>3 слов/с), длинные строки, быстрый темп | UI |
| Жанр с «говорящим» интерфейсом: RPG, визуальная новелла, психологический хоррор с рассказчиком, шутер со статус-баром | UI |
| Камера от третьего лица, фиксированные ракурсы, изометрия | UI (окна) или микс |
| Короткие строки с предметами (часы, дверь, телефон, круг), медленный или средний темп | Мир |
| Liminal, walking sim, «найди аномалию», фольклор, места, полные табличек и вывесок | Мир |
| В тексте есть и мысли героя, и конкретные предметы | Микс |
| В тексте есть экран (канал, звонок, сообщение) | Экран внутри мира (телефон/монитор) — это «мир», даже в UI-режиме удобно держать |

Если сомневаешься — рекомендуй микс для первого лица и UI для третьего.

## Режим «UI»

Текст поверх кадра, в `compositions/hud.html` (GSAP), слово появляется в своё время из `timing.json`.

- Форма подачи — родная для жанра: субтитры рассказчика (засечный шрифт, тёплый цвет, внизу), диалоговые окна RPG с печатью по словам и подписью говорящего, сообщения игры вверху, текстовые окна PS1, уведомления, экран телефона/монитора крупно, экран загрузки или межуровневый титр.
- Одна строка — одно окно; окно закрывается к следующей строке (атрибут вроде `data-hide`). Не держи на экране больше двух строк.
- Подсказки действий (`[E] Open Door`, `Locked`, `[SPACE] to Get Up`) — на языке игры, только пока прицел действительно на объекте, синхронно с действием камеры.
- Окна непрозрачные или почти: полупрозрачные баннеры над 3D читаются плохо.
- Мир всё равно должен «отыгрывать» строку (событие, предмет, свет), иначе это караоке поверх фона.

## Режим «мир»

Каждая строка физически написана на предмете в сцене. Субтитров и HUD нет; `hud.html` не нужен.

- **Сначала инвентарь носителей**: для каждой строки — предмет, который естественно несёт такой текст в этом месте (указатель, плакат, эмалевая табличка, краска/трафарет на стене, мел/уголь, резьба, вышивка, LED-табло, станционные часы, экран, разметка на полу, стикеры, записка). Разные строки — разные носители; повтор носителя оправдан только сюжетом (та же развилка, переписанная во второй раз).
- **Слово открывается в момент пения**: маска слева направо, трафарет на долю, загорание букв табло, луч фонарика «читает» краску. Для каждого носителя заранее готовы все состояния (canvas на слово), в кадре меняется только `material.map` / маска; `CanvasTexture` обновляй только при смене состояния.
- **Читаемость важнее реализма**: надпись в момент пения занимает заметную часть кадра (строка ≥ ~6–8% высоты), смотрит почти в камеру, освещена. Материал Lambert/Standard с `emissiveMap` той же текстуры на 0.2–0.26 — подчиняется свету, но читается в тени. Canvas 1–2K, анизотропия 16.
- **Камера идёт к носителю**: подход/поворот/подъём взгляда, удержание на чтении; не стоит колом — проходит мимо надписи с удержанием взгляда. Носитель должен быть в кадре до первого слова и не уходить до конца строки.
- Ручная работа: буквы по одной с маленьким сидированным поворотом/сдвигом/масштабом, если носитель «самодельный».
- Старый текст можно не убирать, а «стирать» в призрак — полезно для повторов и петель.
- Экраны внутри мира (телефон в руке, монитор, CCTV) — тоже мир; на них удобно ставить строки про канал/звонок/сообщения. Целевое соотношение из удачных роликов: ~80% носителей-предметов, ~20% экранов.

## Режим «микс»

Часть строк в мире, часть в UI. Правило распределения задай заранее и запиши в `DIRECTION.md`:

- В мире — строки с предметом или местом (часы, выход, круг, дверь), строки, на которых камера всё равно смотрит на объект.
- В UI — мысли и вопросы героя, строки без предмета, слишком плотные места, моменты, где камера занята действием.
- Одна строка — в одном месте. Дублировать мир и UI можно только как приём (корабль/мир повторяет мысли героя другим цветом, с подписью говорящего).
- Удачные схемы: краска на стене под фонарём + диалоговые окна; терминалы и мониторы + диалог с подписью (ГЕРОЙ / МИР / ДВОЙНИК); надписи в мире + одна строка в поле ввода телефона.

## Безопасные зоны для 9:16 (TikTok / Reels / Shorts)

Интерфейс платформы перекрывает края кадра 1080×1920. Ключевой текст и события держи в центральной зоне:
- сверху ~160 px — вкладки и поиск;
- снизу ~420 px — подпись, ник, музыка, поле комментария;
- справа ~140 px — лайк, комментарии, репост, аватар;
- слева ~60 px.

Субтитры UI ставь не у нижнего края, а примерно на 62–72% высоты кадра. Носители текста в мире кадрируй в центр. В 1:1 и 16:9 достаточно отступов 6–8% от края.

## Общее для всех режимов

- Время появления каждого слова — из `timing.json` (после правки звёздочек).
- Кириллица только шрифтами с проверенной кириллицей (см. `build.md` → «Шрифты»).
- `check` ругается на `text_occluded` из-за оверлея (CRT, веки): `data-layout-allow-occlusion` ставь на сам текстовый элемент. Перекрытие окон UI — `data-layout-allow-overlap`.
